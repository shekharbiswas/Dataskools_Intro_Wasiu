## 📥 Where data comes from

Data is everywhere. Every click, swipe, tap, scan, and sensor reading can generate useful data.

Let’s break it down into common **sources of data**:

### 🌐 Web and mobile apps

- Track user behavior: clicks, visits, signups, form submissions
- Example: Instagram logs what posts you like and how long you watch videos

### 📝 Forms and surveys

- Structured data collection: names, feedback, choices
- Google Forms, Typeform, SurveyMonkey are common tools
- Example: A post-event feedback form

### 🔌 IoT and sensors

- Smart devices that collect data automatically
- Thermostats, security cameras, fitness trackers
- Example: A smart fridge that logs temperature and power usage

### 💬 Chatbots and messages

- Customer support logs and chat history
- Sentiment and keyword data from conversations
- Example: ChatGPT usage logs, WhatsApp business API messages

### 📂 System and app logs

- Automatically generated by servers and applications
- Contain timestamps, error messages, usage patterns
- Example: Apache access logs showing every visit to a website

### 🛍️ Transactions and payments

- Point of Sale (POS) systems, e-commerce platforms
- Example: Shopify exports sales CSV with time, item, quantity

## 📁 Where we store data

Once we collect data, we need to **store it safely and accessibly**.

Here are some major options and when to use them:

### 🗃️ Local files

- CSV, Excel, JSON, text files
- Easy to start with, great for small projects
- Example: A survey exported from Google Forms as `.csv`

**Pros:**
- Simple and portable
- Works offline
- Easily editable

**Cons:**
- Hard to manage at scale
- Risk of duplication or data loss

<br>

### 🧮 Relational databases

- Store data in rows and columns using tables
- Examples: MySQL, PostgreSQL, SQLite

**Use when:**
- You need to query, filter, and relate structured data
- Data must be consistent and reliable

**Pros:**
- Fast queries using SQL
- Enforces data integrity
- Good for analytics and reporting

**Cons:**
- Needs setup and structure (schemas)
- Less suitable for files or large documents

<br>

### 📦 NoSQL databases

- Flexible data structure: documents, key-value pairs, graphs
- Examples: MongoDB, Firebase Realtime Database

**Use when:**
- Your data doesn’t fit neatly into tables
- You want scalability and flexibility

**Pros:**
- Easy to scale
- Handles unstructured data
- Schemaless (can store varied records)

**Cons:**
- Not ideal for relational data
- Some systems have weaker querying

<br>

### ☁️ Cloud storage

- Store files or datasets in the cloud
- Examples: Google Drive, Dropbox, AWS S3, Azure Blob Storage

**Use when:**
- You need shared access, backups, or large data files

**Pros:**
- Accessible anywhere
- Auto-scaling and secure
- Great for backups and large files

**Cons:**
- Costs money for scale
- May require internet access

<br>

## 🔒 Why storage and access decisions matter

Choosing the right storage system isn't just technical — it's strategic.

### 🧠 Reasons to think carefully about storage:

1. **Security and privacy**  
   - Sensitive customer data must be encrypted and access-controlled  
   - GDPR, HIPAA, and other regulations may apply

2. **Speed and access**  
   - Fast queries can save time and power dashboards  
   - Cloud makes remote collaboration possible

3. **Scalability**  
   - Your small CSV today may become 1 million records tomorrow  
   - Plan for growth by picking scalable solutions

4. **Cost efficiency**  
   - Cloud pricing models can get expensive if unmanaged  
   - Local storage is free but not always safe

5. **Data integrity and structure**  
   - Databases prevent accidental changes, missing values, and duplicates  
   - Spreadsheets are flexible but error-prone

6. **Automation potential**  
   - Structured storage makes it easier to automate reporting and analysis  
   - Integrations often depend on predictable schemas

## ☕ Café Sales Data Project

This README outlines how a small café might think about collecting and storing daily sales data, along with an exploration of common data tools.

### 🔍 Tool Review

**Google Sheets**  
- Good for: Small, structured data (tables, surveys)  
- Strengths: Easy to use, collaborative, beginner-friendly

- Good for: Structured tabular data

- Good for: Semi-structured or flexible schema (like product reviews or form data)

- Good for: Real-time, app-based data (chat apps, sensors)
