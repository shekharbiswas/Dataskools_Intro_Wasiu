# 🔗 How things work together: your _Learning System_

You’ve now seen tools like **Slack**, **Zoom**, **Google Calendar**, and **GitHub** — but how do they work together to support your journey?

At first, it might feel like a bunch of separate platforms.  
But when used with purpose, these tools become a system — your **learning environment**.

Each one plays a different role:
- One keeps you on schedule  
- One connects you with others  
- One stores your progress  
- One helps you ask questions and grow  

Together, they create a space where learning feels connected, clear, and supported.

This system isn’t just about technology. It’s about helping **you** stay focused, consistent, and visible in your work — even on the tough days.

Let’s zoom out and look at the big picture of how it all flows.

## 🧠 The Big Picture: Your Learning Ecosystem

Think of these tools like teammates on a project. Each one supports a part of your workflow.

| Tool              | What It’s For                                 | How You’ll Use It                        |
|------------------|------------------------------------------------|------------------------------------------|
| Zoom             | Live learning and real-time sessions           | Join weekly check-ins and live workshops |
| Google Calendar  | Organizing your time and accessing sessions    | Accept invites and get reminders         |
| GitHub           | Storing and sharing your learning progress     | Save notes, write READMEs, track growth  |

These tools aren't separate — they work together to help you stay focused and feel supported.

<br>

## 📅 How It All Flows Together

1. 📬 You receive a calendar invite  
2. 🔔 Calendar reminds you before the session  
3. 🎥 You join the Zoom session and participate  
4. ✍️ You take notes, do exercises, or reflect on the topic  
5. 💻 You upload your notes or reflection to GitHub  

Every tool has a purpose — and everything connects.

<br>

## 📝 Markdown: Your Writing Tool for GitHub

GitHub uses a simple formatting language called **Markdown**. You’ll use it to write your `README.md` and notes.

Here’s a quick cheatsheet to get started:

### 🧾 Basic Markdown Format

<pre>
# Heading 1
## Heading 2
### Heading 3

**Bold text**  
_Italic text_  
- Bullet point  
1. Numbered list  
[This is a link](https://example.com)

> This is a quote

`Inline code`
</pre>

📚 For more examples and extended syntax, visit:  
[Markdown Guide – Basic Syntax](https://www.markdownguide.org/basic-syntax/)

You can try editing an existing README or create a new `.md` file and experiment.

<br>

## ✍️ README Writing Tips

Your README file is like your **learning journal** or **portfolio homepage**.

Use it to:

- Introduce who you are and what you're learning  
- Track what you worked on this week  
- Write down questions or reflections  
- Add links to things you created or explored  
- Show your growth over time  

Keep it clean, personal, and updated — your README tells your story.
